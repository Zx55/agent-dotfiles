# Bridged Networking and Temporary Proxy Access

MiPlay needs direct LAN discovery and reachable media URLs. Give the VM its own LAN presence with UTM bridged networking. Use an SSH reverse tunnel only when installation or update traffic cannot reach GitHub or Docker Hub directly.

## Configure the UTM NIC

Stop the VM before editing its virtual hardware. Configure:

- Network mode: `Bridged (Advanced)`
- Bridged interface: the active wired Ethernet-class interface when available
- Emulated network card: `virtio-net-pci`
- MAC address: keep the value generated by UTM

The MAC address belongs to the VM's virtual NIC, not to the Mac host or physical Ethernet adapter. Do not click `Random` after using this MAC for a DHCP reservation.

One physical interface can bridge multiple VMs. Each VM has its own MAC and IP, so equal service port numbers on different guest IPs do not conflict.

## Verify the Bridge First

Boot the Ubuntu installer with IPv4 set to DHCP before assigning a static address. A correct bridge receives an address from the physical LAN. An address from a UTM-only subnet means the VM is still using shared networking or NAT.

Use the temporary DHCP result to verify the expected subnet, gateway, DNS, Internet access, and selected bridge interface. Do not derive a permanent address from assumptions alone.

## Choose the Stable Address Strategy

Prefer these strategies in order:

1. Router DHCP reservation for the VM's fixed virtual MAC.
2. Guest static IPv4 outside the router's DHCP allocation pool.
3. Ordinary DHCP only as a temporary installation state.

When the router cannot be configured, identify an address outside the DHCP pool. A failed ping and an incomplete ARP entry only show that no device responded at that moment. They do not prove the router will never lease that address.

## Configure a Guest Static Address

In the Ubuntu Server installer, select the guest interface, choose `Edit IPv4`, and set `IPv4 Method` to `Manual`.

Fill these values from the actual LAN:

```text
Subnet:        <network>/<prefix>, for example 192.168.1.0/24
Address:       <unused address outside the DHCP pool>
Gateway:       <router LAN address>
Name servers:  <working DNS addresses, comma separated>
Search domains: leave empty unless the LAN uses one
```

Keep IPv6 automatic unless the user has an intentional IPv6 plan. After saving, confirm the installer reports `static <address>/<prefix>`. The word `static` is status output, not another selectable interface.

## Verify After Boot

From the Mac:

```bash
ping -c 2 <vm-ip>
nc -vz -w 3 <vm-ip> 22
```

From Ubuntu:

```bash
ip -4 address show dev enp0s1
ip route show
resolvectl status
ping -c 2 <gateway>
curl -I --connect-timeout 8 https://github.com/
```

Do not deploy MiPlay until the address, route, and DNS checks pass. A failed external request can be handled temporarily with the proxy tunnel below.

## Use the Mac Proxy Temporarily

Use this only for network-dependent installation or update operations. The local proxy may continue listening only on the Mac loopback address. Do not enable LAN access.

Start a controlled SSH reverse tunnel from the Mac while its HTTP or mixed proxy listens on `127.0.0.1:7897`:

```bash
ssh -M -S /tmp/miplay-proxy-%C.sock -fNT \
  -o ExitOnForwardFailure=yes \
  -o ServerAliveInterval=30 \
  -o ServerAliveCountMax=3 \
  -R 127.0.0.1:7897:127.0.0.1:7897 \
  <ssh-alias>
```

The reverse tunnel creates a VM-local proxy endpoint at `http://127.0.0.1:7897`. Verify it before continuing:

```bash
ssh -S /tmp/miplay-proxy-%C.sock -O check <ssh-alias>
ssh <ssh-alias> \
  'curl -x http://127.0.0.1:7897 -I --connect-timeout 8 https://github.com/'
```

Pass that URL only to operations that need it:

```bash
sudo bash /tmp/install_docker.sh \
  --proxy-url http://127.0.0.1:7897

sudo bash /tmp/install_miplay.sh \
  --hostname <vm-lan-ip> \
  --proxy-url http://127.0.0.1:7897
```

The installers use the proxy for package downloads, Git operations, Docker image pulls, and image build steps as applicable. They remove their temporary Docker daemon proxy before exiting. The running MiPlay container does not inherit the proxy.

Close the tunnel after the network-dependent work finishes:

```bash
ssh -S /tmp/miplay-proxy-%C.sock -O exit <ssh-alias>
```

Do not place this proxy in `/etc/environment` or leave it permanently attached to the Docker service. A persistent proxy would fail whenever the Mac proxy or SSH tunnel is unavailable.
